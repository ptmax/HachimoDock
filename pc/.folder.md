# Desktop source (0.1.168)

- src: React UI, generation pipeline and regression tests.
- src-tauri: native device, audio, desktop integration and local configuration.
- src-tauri/bridge: local Agent session event bus and receipt handling.
- builtin-clawpkgs / new-components: public widget packages and source assets.
- scripts: resource preparation, tests and public distribution checks.

The bundled catalog follows the firmware factory list (28 components). Media
contract tests use independent offline fixtures under tests/fixtures. Official
community staging uses the same current catalog.

Public source uses user-provided credentials and per-computer networking settings. service_credentials.rs only rejects a legacy non-secret placeholder; it does not supply service defaults. Configure your own service keys in API settings. User configuration and caches are runtime data, never build inputs. See the repository README for build and release instructions.

Long-reply USB CDC recovery is bounded on both sides: `usb_serial.rs` keeps the port alive through at most five consecutive transient tty timeouts on audio chunks or frames sent during active realtime capture (any successful write resets the budget; permanent errors and non-realtime frames still disconnect), and `realtime_chat.rs` drops a stalled 100 ms chunk and resumes on the next one, ending the session only after three consecutive stalls or a permanent transport error. Diagnostics stay metadata-only (`playback_write_gap`). See `docs/p4-usb-cdc-long-reply-diagnosis-2026-11-03.md` (workspace docs) and `docs/realtime-chat.md`.

macOS background USB reconnect: `run()` holds a process-lifetime NSProcessInfo activity (`realtime_audio_macos::ProcessActivity`, options `UserInitiatedAllowingIdleSystemSleep | LatencyCritical`; it never sets PreventSystemSleep), while the keep-awake switch keeps choosing only the caffeinate mode (`-u` off / `-imsu` on). The host heartbeat now proves liveness with a requestId + `protocol/ack` (`usb_serial::probe_liveness`, bounded 4 s) because a stale tty after sleep keeps accepting writes; this runs for `esp-p4` runtimes while legacy runtimes keep the bounded write-only heartbeat. Failures record `liveness_probe_failed`/`forced_reconnect` and fall back to the existing auto-connect probe. A wall-clock vs monotonic gap triggers an immediate probe after wake. Tests lock the no-PreventSystemSleep options, keep-awake semantics and the ack/timeout path.
