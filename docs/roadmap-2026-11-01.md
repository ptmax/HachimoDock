## 6. Adjustable bubble opacity without hurting readability

- [ ] New branch: `feature/bubble-transparency`.
- [ ] The current bubble/session-card surface is opaque white, so it hides the
  character animation behind it.
- [ ] Add a user-adjustable bubble opacity setting in the App and persist it with
  the existing appearance/device display settings.
- [ ] Keep text opacity at 100% and enforce a minimum contrast ratio against the
  composited background; use an adaptive scrim/outline/shadow when the underlying
  animation is bright, rather than lowering text contrast with the panel.
- [ ] Use a safe lower bound for the panel alpha (for example 40–50%) and a sensible
  default that leaves the animation visible; allow restoring 100% opaque.
- [ ] Apply the setting consistently to normal, compact and realtime conversation
  bubbles, including device-font fallback and host-rendered text-image paths.
- [ ] Watch the P4 render budget: alpha compositing must stay inside the existing
  per-frame budget and must not introduce full-screen read/modify/write passes.
- [ ] Verify on the integration branch with the character animation running behind
  bubbles, and check Chinese/English/Markdown text at every opacity step.

## 7. DSH stop must not look like a completed turn

- [ ] Stopping the current DSH session from the DSH client, or through the
  HachimoDock client, still renders the P4 session as completed and plays the
  completion animation/sound.
- [ ] `turn/end` currently maps every ending to `done` in the DSH bridge,
  regardless of `data.reason.kind`.
- [ ] Map `completed` to the normal done path, but map `aborted` / `interrupted`
  (and other non-completed endings) to a stopped/interrupted state that does not
  trigger the completion animation or completion cue.
- [ ] Keep approval-expired and explicit device interrupt behavior consistent;
  do not suppress a genuinely completed turn.
- [ ] Verify: DSH client stop, P4 interrupt action, approval timeout, and a normal
  completed turn produce distinct device states and sounds.

## 8. DSH assistant text never reaches the P4 bubble

- [ ] The P4 currently shows only the DSH session title and lifecycle state, with
  no assistant body or Markdown, so PR #12 text rendering is not exercised.
- [ ] Not a PR #12 regression: the DSH Host summary contains only
  `title`/`status`/`state`; the DSH adapter's `normalizeSession` has no
  `displayContent`, and the bridge does not forward `assistant/message` text.
  Codex/Claude publish `displayContent`; DSH does not.
- [ ] Add a bounded last-assistant-text cache in the DSH bridge and include
  `displayContent` in `/sessions` and incremental `session` events.
- [ ] Map it through the DSH adapter and `formatDeviceSessionContent` so P4 session
  cards receive the same body text path as other agents.
- [ ] Keep the body bounded and do not forward transcripts wholesale; sanitize
  Markdown to the subset the P4 renderer supports.
- [ ] Then re-run the Chinese/Markdown, bold, list, link and code-block tests on the
  integrated display branch.
