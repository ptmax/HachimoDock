# Firmware repair baseline

This folder remains based on PC-bundled 0.7.103, not the experimental 0.7.108 branch.

Public revision `0.7.103-p4-r2` accompanies desktop `0.1.168` as a maintenance
release. Experimental framework work is not part of this build.

The factory and OTA bootstrap catalogs contain 28 built-in components, with
`cloud-hop` as the factory default. Launcher thumbnails are regenerated from the
same catalog. Generic media parsing, rendering and playback remain available;
their regressions use isolated synthetic fixtures, not a bundled live service.

`main/pet_p4_miniapp.c` owns transactional component storage and per-component recovery from verified committed catalogs. Navigation persists only the last-opened ID, leaving the previous catalog available for recovery. Unparseable existing catalogs block destructive bootstrap reseeding. Known image-free bootstrap packages are distinguished from complete resources.

`main/pet_p4_protocol.c` exposes resource integrity and bounded resource-repair installation. Repairs retain component records and existing button configuration, and refuse writes during audio activity. `tools/build_builtin_bundle.py` emits bootstrap identity checks without inflating the bundle. `tests/component_resource_recovery_test.py` executes production recovery logic with sanitizers; fault injection belongs in offline tests, never on user storage.

`main/pet_p4_protocol.c` + `main/pet_p4_renderer.c` + `main/pet_p4_input.c` implement the R5 device-side DSH approval path: `approval/request` stores one bounded pending request (`requestId` 96 / `agent` 64 / `tool` 64 / `reason` 192 bytes, 30 s default deadline), the renderer paints a modal `需要授权` card above the active page, and SW1/SW3 short presses send exactly one `approval/decision` before clearing. Expiry drops the modal without sending a decision; replayed request IDs are ignored. `tests/protocol_contract_test.py` locks the topic/state/UI/input contract.

`main/pet_p4_renderer.c` applies the App-persisted `ui/bubble_opacity` value once per frame at the top of `pet_p4_renderer_render()`, so the idle compact bubble, Agent session cards and the realtime conversation card all dim together. Card surfaces use the PPA alpha path; titles, bodies and labels remain fully opaque. `tests/p4_bubble_opacity_test.py` locks that contract.

`main/pet_p4_main.c` keeps the transport RX path bounded under host backpressure: the USB Serial/JTAG reply route queues complete frames instead of waiting for TX-idle (the drained UART path and the screenshot barrier stay), protocol-queue overflow is rejected through a non-draining send so the RX task never blocks on TX, and the protocol queue depth is 48. `tests/protocol_contract_test.py` locks these bounds.

`main/pet_p4_audio.c` suppresses event cues (`permission_request/approved/denied/expired`, `session_terminated`) while the realtime audio pipeline owns the codec: an active realtime conversation, streamed playback, microphone capture/capture-request, music, instrument or fruit audio. Approval decisions still send `approval/decision` and clear the modal before the (ignored) cue call; the option remains the only difference, and audible approval feedback is preserved outside those states. `tests/p4_event_cue_guard_test.py` compiles the production guard and locks the suppressed states; `tests/system_cues_test.py` locks the decision-before-cue order and the shared approval/cancel path.

`main/pet_p4_audio.c` treats microphone capture as an exclusive owner while the audio task can still be inside the codec: `capture_owns_microphone()` blocks status-cue selection and cue playback, and every capture stop (PTT, conversation, owner-scoped control) clears the request and then waits at most 100 ms (`PET_P4_AUDIO_CAPTURE_STOP_SETTLE_MS`) for `g_capture_active` to clear before the caller resumes overlays/approval replies/ASR. This is a bounded settle barrier, not a watchdog or stack workaround. `tests/p4_capture_teardown_test.py` compiles the production stop/guard code with mocked atomics and locks the guard usage in `pet_p4_audio_process` and `playback_task`; `tests/system_cues_test.py` keeps the event-cue guard contract.

`main/pet_p4_diagnostics.c` prints the persisted boot/reset record once per boot (`boot=… reset=… fault=… last_fault=…`) after `init_usb()`/`init_uart()`, so a UART/USB console capture keeps the reset reason without a later diagnostics query. `tests/p4_boot_observability_test.py` locks the ordering and the reset-reason source; the console line is not a protocol frame.
